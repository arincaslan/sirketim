# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Sirketim is a solo-founder, multi-department agency workspace, not a single codebase. Claude Code subagents act as each department's actual workers (drafting, research, first-pass production), not just copilots; the founder reviews and decides. Eight departments: web development, architecture (real building/interior design), sales, advertising, communication, content (long-form/affiliate content production), accounting, control/audit. A three-member board (COO, CFO, Controller) sits between the founder and the departments — see `shared/board.md`.

## Commands

Every Next.js project (client or product) is self-contained, its own `package.json`. **`cd` into the specific project before running anything** — no lint/test at the repo root, no monorepo tooling.

**Exception: a deploy shim at the repo root**, for Cloudflare's benefit only. Root `package.json` has two scripts — `build` (delegates into `products/affiliate-sites/fragrance-dupes`) and `postinstall` (runs `scripts/ci-postinstall.mjs`, gated on `WORKERS_CI`/`CF_PAGES`/`CI` — Cloudflare's automatic dependency install is the only hook that reliably fires) — plus a root `wrangler.jsonc` and `package-lock.json` (its absence makes Cloudflare pick bun, which deletes the empty lockfile and skips the build). This exists because Cloudflare runs `wrangler deploy` from the repo root when a project has no "root directory" configured.

**Verify a change here with `rm -rf out && WORKERS_CI=1 npm install` from the root — `npm run build` at the root is NOT what Cloudflare runs and proves little.** Two "fixes" shipped broken because they were verified with the wrong command.

Not a workspace root, no dependencies of its own: a second deployable site gets its own Cloudflare project with a root directory configured, not a change here. Deploy settings: `departments/web-development/CLAUDE.md`.

**Live site: `counterscent.com`** on Cloudflare Workers, $0/mo, HTTPS valid, GA4 collecting, Search Console verified. Renamed from `parfumoza.com` 2026-08-27 after a trademark-adjacent name collision (Parfumo.com, Parfumado.com) — read `products/affiliate-sites/fragrance-dupes/CLAUDE.md` before proposing any brand name, the vetting rule that came from this applies everywhere. **Closed 2026-09-10: `parfumoza.com` was removed from Cloudflare** and verified dead from outside — no A/AAAA record, nothing answers on http or https. Its registrar NS delegation still points at Cloudflare, which is a loose end rather than a live risk. DNS/mail record set (MX/SPF/DKIM/DMARC): `departments/web-development/counterscent-dns-migration.md` — a proxied CNAME breaks DKIM signing, go there before touching DNS.

**GA4 is deliberately cookieless** (`components/kit/Analytics.tsx`, `client_storage: 'none'` + `anonymize_ip`) — this is also why the site carries no consent banner under KVKK/ePrivacy. No client ID means *Users* inflates toward *Sessions*, in the direction that flatters us. **Never quote GA4 Users on an affiliate application**; use Cloudflare Web Analytics instead. **Never declare this site up/down from one local `curl`** — force-resolve (`curl --resolve <domain>:443:<cloudflare-ip>`) and check an external resolver (1.1.1.1/8.8.8.8). A stale local router DNS cache serving a parked-page IP has produced false "site is down" reports here more than once; the reverse mistake (declaring it down on one bad lookup) has also happened.

Real projects: `products/web-templates/` (`agency-landing`, plus `fragrance-store`/`-2`/`-3` — three deliberately distinct palettes; check a new template's direction against the others' before committing) and `products/affiliate-sites/fragrance-dupes/` (own CLAUDE.md). Inside any: `npm install`, then `npm run dev`/`build`/`lint`. No test script anywhere — don't invent one, verify against real rendered output. Same pattern once `new-web-client` scaffolds a client under `departments/web-development/clients/<slug>/`.

**Never run `npm run build` while `npm run dev` is live in the same project** — both write `.next/` and the collision corrupts the manifest badly enough that dev starts 404ing every route. Recovery: kill both, `rm -rf .next`, run one at a time.

Setting up on a different machine: `SETUP.md`.

- **Architecture tooling**: CAD via Python `ezdxf`/`svgwrite` through `departments/architecture/lib/cadgen/`; DWG conversion via ODA File Converter (per-user install — exact path and the `ezdxf` `win_exec_path` gotcha in `departments/architecture/CLAUDE.md`); scanned-PDF reading via Poppler (system-wide); 3D rendering via Blender 4.5 headless (`bpy` needs an explicit import). See `departments/architecture/CLAUDE.md`.
- **MCP servers**: `.mcp.json` configures 9 — `openart`, `21st` (needs `TWENTY_FIRST_API_KEY`), `chrome-devtools`, `fanvue` (`ad-strategist` only, gated on a real KYC'd account that doesn't exist yet), `motion` (`https://mcp.motion.so/mcp`, `web-developer` only as `mcp__motion`, added 2026-08-25 after the founder rejected a hand-drawn SVG illustration outright — **its pricing is unconfirmed, don't run an actual generation through it until real cost is confirmed and the founder OKs the spend**; see `departments/web-development/CLAUDE.md`), plus 4 Hostinger servers (`HOSTINGER_API_TOKEN`, per-machine env var, never committed). Hostinger's `billing`/`ecommerce`/`reach` deliberately excluded. `eromify`/`zencreator` were configured then **removed 2026-08-22 at the founder's repeated instruction** — no NSFW-capable generator is configured; don't re-source one (see `departments/advertising/CLAUDE.md` and memory `feedback_no_unrestricted_content_tooling`). **`claude mcp list` is unreliable** — it has reported a server pending while the server's own tool worked fine. If a connector matters, call one of its actual tools (or `ToolSearch`) rather than trusting the list. **A `CONNECT_TIMEOUT` at session start means "start a fresh session," not "the server is broken"** — confirmed while the same servers worked from another terminal at the same moment. Applies doubly to background subagents, which don't inherit a fresh session's connections.
- **Third-party skills**: `.claude/skills/` mixes repo-authored skills with symlinks into `.agents/skills/` (external installs via `npx skills@latest add`, tracked in `skills-lock.json`) plus `ui-ux-pro-max` as a real directory. **Count it, don't trust a number written here:** as of 2026-09-02 it holds 6 repo-authored skills + `ui-ux-pro-max` + **13 symlinks** — the doc previously said a `uipro` run bundles 6 extras and one of them is `design`, and neither is true of the current tree (no `design` symlink exists). The durable rule is the reason behind it: **a bundled `design` skill shadows Anthropic's built-in Design skill, so after any `uipro init`/`update` list `.claude/skills/` and delete what that run added.** `.agents/skills/` and its symlinks are gitignored by design and don't travel via clone/pull — if a session needs one and it's missing, re-run the install rather than assuming it exists because this doc says so.
- **Git remote**: `https://github.com/arincaslan/sirketim`, **public** — deliberate, to unblock claude.ai's GitHub connector. Two scheduled routines (`board-cfo`/`board-controller` weekly reports) push to `main` directly — a `git pull` may surface files you didn't create.
- **Run `git fetch origin` at the start of every session**, before any status question or board delegation. Board subagents have no Bash/git access — they only see the local working tree and can't discover work on an unmerged remote branch. Check `git branch -r` and `git log main..origin/<branch>` and surface/merge what you find first.
- **Two machines, two usernames** (`win10`/`Semih`) — a hardcoded `C:\Users\<name>\...` path is wrong on whichever machine didn't write it (broke `export_dwg.py`'s ODA path for real). Check against `$env:USERNAME` before trusting a hardcoded local path; system-wide installs avoid the problem, per-user ones need this check.
- **Payment/payout providers**: Sirketim is a Turkey-based A.Ş. — **Stripe, PayPal, and Gumroad's payout rails don't serve Turkey.** Usable: **Paddle**, **iyzico**/**PayTR**, **Payoneer**. Check `departments/accounting/CLAUDE.md` before building on any provider — a full Stripe integration was built for fragrance-dupes two days after this repo had already documented Stripe doesn't serve Turkey.
- **`board-cfo`/`board-coo`/`board-controller`/`accountant`/`auditor` have no `WebSearch`/`WebFetch`** — they reason from training cutoff plus what's on disk. Have them flag unverifiable provider/pricing claims explicitly, then verify from the top level before anyone builds on them. Also sanity-check anything `WebFetch`'s own summarizer returns against what you already know — it has stated at least one flatly false provider fact with confidence.
- **Downloaded vendor/licensed data lands at the REPO ROOT, which is not gitignored — and this repo is public.** Move it into the project's ignored `scripts/feeds/` and confirm with `git check-ignore <path>` before any `git add -A`. This nearly committed licensed merchant data twice on 2026-09-05.
- **Identify a merchant or vendor by the DOMAIN in its account record, never by a name search.** Near-identical trading names inverted a whole phase's plan for two days — `fragranceshop.com` (our CJ advertiser, genuine originals retailer) vs `thefragranceshop.com` (an unrelated dupe house) vs `thefragranceshop.co.uk` (a third company).
- **Most files here are CRLF.** A script that splits and joins on `\n` rewrites every line and buries the real change: a 2-line dashboard edit shipped as a 1854-line diff. Split and join on the file's own terminator, and when a diff looks too large run `git diff --ignore-cr-at-eol --stat` before committing. Note also that `npm install` mutates `package-lock.json` as a side effect (`dev` → `devOptional`) — unstage that unless the dependency change is the point, because the lockfile decides which package manager Cloudflare picks.
- **Assert against the shipped code, not a reimplementation of it.** `npx esbuild verify.ts --bundle --platform=node --format=esm --alias:@=.` imports `lib/` directly so you can run the project's real functions over real data. Reimplementing a formula only re-tests your own arithmetic — and on 2026-09-05 this caught a bug in the *check* (a slug passed where the function wanted an object) that would otherwise have read as 37 broken listings.
- **A seller's marketing copy is not a product fact, in either direction.** Don't repeat it as truth, and don't infer a defect from it either: "Essential Oil Fragrance" in every title nearly became fifteen invented format claims about a real company whose own ingredient lists start `alcohol, aqua`. Attribute it, or verify against something the seller cannot spin.
- **Affiliate attribution can live in the network's click cookie rather than in the destination URL.** Asserting it must survive into the final URL falsely condemned nine working links as unattributable. Trace the hops and accept either channel.
- **A product feed's image URLs decay** — CDN paths are content-addressed, so one re-upload 404s every image in the feed. Fall back to the merchant's own product JSON and report which images were rescued that way, so a rotting feed is visible rather than silent.
- **A script serving several merchants must degrade to the ones it can still serve.** Feeds are gitignored and expire, so check the cheap local condition (is this file already downloaded?) BEFORE reading the expensive shared input, and treat an unreadable input as that merchant's failure rather than the run's. Reversed, one expired feed aborted every merchant's fetch — including entries whose images were already on disk and would have been skipped a line later.
- **Do not judge a merchant by the feed it happens to send you.** Perfumania's CJ export was 66 rows of its own house dupe line and read as a dead end; its storefront is 4,380 products across 480 vendors, including six of the references our other originals merchant cannot stock. Check the actual shop before concluding a partner is not worth wiring - and note the corollary, that a public Shopify storefront can be a better source than the feed, via `/collections/all/products.json?page=N` (the bare `/products.json` caps at 250 and silently ignores `since_id`, and a search-suggest endpoint is too unstable to prove absence with).
- **A vendor's structured data can contradict ITSELF - measure it against something you already trust before building on it.** Perfumania publishes proper three-tier note pyramids on 1,829 products, which looked like a research shortcut. Against the 90 fragrances where we hold our own researched pyramid, the two agree on 0.57 of the materials named; 59% of the merchant's own duplicate SKUs disagree with each other, and one product carries four different pyramids. Machine-readable is not the same as correct.
- **Two sources feeding one flat keyed map must not share a key prefix.** Both originals merchants were keyed `original-<slug>` and collided on 91 of 123 ids, where spread order silently decided which retailer survived and the other's links vanished with no error anywhere. Namespace per source, and when a build step reads those files as text, add the new one there too or its links resolve in the UI and 404 at the edge.
- **When one script verifies what another produces, they must read the same source list from the same place.** A verifier that keeps its own copy drifts, and it drifts silently in the direction that flatters: Counterscent's link checker fell two source files behind its generator and reported a clean pass over 368 unchecked live links, under a comment asserting the two agreed. A checker covering a subset is worse than no checker, because it converts "we have not looked" into "we looked and it was fine". Extract the list, import it from both.
- **Widening what a check KNOWS about must not silently widen what it DOES.** The same fix tripled a script's coverage, and because every check there is a real affiliate click, it would have fired 620 sequential clicks from one IP - a pattern a network can read as fraud, with account termination rather than a warning as the penalty. Sample by default, make full coverage an explicit flag, and print what was skipped.
- **Never let the party being measured supply both inputs to the check that measures them.** Counterscent's copy-detection gate compares a producer's notes AND facets against the original, and works only because facets are ours; collecting both from the producer defeats it by construction and would make rank purchasable in substance while remaining unpurchasable in letter. The same shape recurs anywhere a submitter fills in the fields a fraud check cross-references.
- **A subscription and a commission taken from the same counterparty is a conflict you then have to keep explaining away; taking only one removes it.** For Counterscent's producer programme the founder chose no commission on paid tiers, which means we earn nothing from where a paying producer ranks - a stronger version of "no tier buys rank" than any policy statement, because it is structural rather than promised.
- **A subagent refusing a brief is a success mode, not a failure.** One refused to write fifteen invented format claims about a real company rather than comply; that was the correct call, and the brief was wrong.

## Architecture

CLAUDE.md files nest and each layer adds scope: this root file → `departments/<dept>/CLAUDE.md` → `departments/<dept>/clients/<slug>/CLAUDE.md`, plus `products/affiliate-sites/fragrance-dupes/CLAUDE.md`. Read the relevant chain before department or client work.

- **Subagents** (`.claude/agents/`) map 1:1 to departments. **Verify a subagent's claimed file write before relaying it as done** — `board-coo` once reported writing a plan doc and delegating three sub-tasks in convincing detail, and none of it existed on disk. Risk concentrates in multi-layer delegation (top level → board → department). Fix: `Glob`/`git status`/`Read` the claimed file yourself, or brief leaf subagents **read-only, text-return-only** so nothing can be fabricated as "written."
- **Board members** (`.claude/agents/board-*.md`) sit above departments, not as an 8th one — `board-coo` (web dev, architecture, sales, advertising, communication, content), `board-cfo` (accounting), `board-controller` (control/audit). Brief the board member with an outcome; it delegates and reports a synthesized result. See `shared/board.md`.
- **Skills** (`.claude/skills/`): `new-web-client`, `project-brief`, `client-proposal`, `campaign-brief`, `product-listing`, `affiliate-content`. Prefer these over freeform work when a task matches one.
- **`products/`** (Sirketim's own sellable goods, sold via marketplaces) vs **`departments/<dept>/clients/`** (client-commissioned work). See `products/README.md`.
- **`products/affiliate-sites/fragrance-dupes/`** ("Counterscent") is the most complex codebase here and the only one with its own CLAUDE.md — **read it rather than relying on this summary.** Two invariants worth repeating at this level because both are easy to violate silently: (1) the displayed match score is capped, never the raw computed one — an uncapped score lets a copied note pyramid score exactly 100%, which is why **nothing publishes above 95 now** (structural ceiling, 2026-09-08) and an unverified listing still stops at 90; (2) **affiliate buy links 404 under `npm run dev`** and always will — `public/_redirects` is a Cloudflare-only file that `next dev`, `next start` and `npx serve` all ignore. `npm run preview` (build + `wrangler dev` on :8788) is the only local way to click one. This cost a founder click to discover after the links had been "verified" with curl.
- **`internal/dashboard/`** is static, no server/build. Two files that can drift — `design/Main.dc.html` (Claude Design canvas, Desktop-edited) and `design/sirketim-dashboard.html` (hand-written, published via `Artifact`, what's actually live). **Update both whenever a task changes**; matching `id`s make them diffable. **Republishing this or the Counterscent Finalization report is not free**: pass the artifact's existing `url` (without it you create a duplicate and the founder's bookmark keeps opening the stale page), and the tool refuses until you have `Read` the live copy in **full** — ~786 lines for the dashboard. Plan that read into the session rather than discovering it at the end. URLs and which artifact is currently behind: `HANDOFF.md`.
- **`shared/clients.md`** (client/lead registry), **`shared/board.md`** (board charter), **`shared/brand.md`** (placeholder).
- **Connector status**: `.mcp.json` for MCP servers, each department's CLAUDE.md "Recommended connectors" section for everything else.

## Conventions

- Client work: `departments/<department>/clients/<slug>/`. Products: `products/<line>/<slug>/`. Slugs are lowercase-hyphenated.
- Register every client/lead in `shared/clients.md` as soon as they're qualified.
- Every transaction gets a row in `departments/accounting/ledger.md` when it happens, not retroactively.
- **Don't claim a connector, deploy, or post happened if it isn't actually configured** — say what's missing instead. The same rule applies to shipped UI: a feature whose backing service doesn't exist yet must say so at the point of use (an explicit "not live yet, nothing was saved" state, or a 503 with a reason) — never a fake success.
- **Fixture and placeholder data must be labelled as such in the file that holds it**, with what would make it real. Where fabricated data would be actively harmful if published — invented customer reviews about real companies, for instance — say that too, and make the *rendered UI* say it as well; a label in the data file does not protect the component that renders it. `products/affiliate-sites/fragrance-dupes/lib/reviews.ts` carried exactly this warning while the component ignored it and rendered six invented reviews about real, named companies — FTC Fake Reviews Rule and trade-libel territory, not a tidiness problem.
- **These CLAUDE.md files go stale faster than the code, and confidently.** Treat any concrete claim here (a file exists, a route, "this returns 503") as a hypothesis to verify, not a fact, before building on it. When a change makes a documented claim false, update the doc in the same change. **This applies hardest to a documented CAUSE of a known gap**, which nobody re-tests because the gap is already acknowledged: a note saying 24 images needed all three feeds present was wrong (they needed one, which was on disk) and it kept the gap alive for two days. A stated reason is a hypothesis too.
